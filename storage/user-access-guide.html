2. Quick Access Map

HIVE.OS is a permission-aware, multi-context application. The same user may see a different menu depending on whether they are working in the central platform or inside a tenant node, and the same page may show different actions depending on the role attached to the session.

Workspace Main route Who usually sees it What users do there

Tenant Management /dashboard/tenants Central tenant administrators Provision, inspect, suspend, reconfigure, and purge tenant nodes.
Identity & Access /dashboard/security Security and operations roles Manage operators, access roles, and the permission dictionary.
Audit Logs /dashboard/audit-logs Auditors, admins, compliance users Search live logs, inspect archived logs, set retention, archive records, and run exports.
Storage /dashboard/storage Users with storage management permission Upload, organize, preview, edit, share, favorite, restore, and permanently delete files.
Settings /dashboard/settings Configuration owners Manage brand, general settings, localization, and backups based on tab-level access.

Profile Settings /dashboard/profile Any signed-in user Update personal details, avatar, and two-factor authentication.
API Docs /dashboard/api-docs Technical users Switch between central and tenant API testing modes and use interactive Swagger docs.
Document Converter /dashboard/tools/converter Storage-enabled power users Upload HTML, use IDE mode, attach assets, generate PDFs, and save results back to storage.

Central context

Central users can see cross-platform functions such as tenant management, global alerts, central dashboard metrics, and control-plane API testing.

Tenant context

Tenant users work inside one node. Tenant-specific quick actions stay visible, while central-only modules such as tenant management are hidden.

Why menus differ

The UI checks permissions from the signed-in user object and only renders modules or actions that the current session is allowed to use.

Full-access shortcut

In the frontend permission helper, the roles Super Admin and Admin are treated as full-access roles for permission-gated UI.

3. Getting Started

3.1 Central Sign-In
  1. Open the main HIVE.OS address for the environment you are using.
  2. Go to /sign-in.
  3. Enter the email address in the System Identifier field.
  4. Enter the password in the Encryption Key field.
  5. Select the login button to begin the authenticated session.
3.2 Tenant Sign-In
  1. Open the tenant-specific hostname or subdomain.
  2. The app automatically detects the tenant host and switches to tenant login mode.
  3. Enter email and password as usual.
  4. The session is validated against the tenant user endpoint instead of the central one.

Local tenant development is designed around subdomains such as tenantapple.localhost.

3.3 Two-Factor Authentication
  • If 2FA is enabled for the user, the system redirects to the 2FA page after the first login step.
  • The user enters a 6-digit authenticator code.
  • If global 2FA is enforced and the user has not set it up yet, the page shows a QR code and manual secret key first.
  • The same tenant-aware logic applies here, so tenant users confirm their 2FA against tenant verification endpoints.
  • Users can abort the 2FA step and return to sign-in, but they cannot complete login without satisfying the security requirement.
Important: a user can authenticate successfully and still have limited access after login. Authentication and authorization are separate: the first proves identity, the second controls what the user can see and do.
3.4 What Happens After Sign-In
  • The app stores the access token, user record, and context information in local storage.
  • The user is redirected to /dashboard.
  • The dashboard shell periodically re-syncs the user session when navigation changes or the browser tab regains focus.
  • If the token is missing or invalid, the app clears the session and sends the user back to sign-in.
  • If the backend returns a critical access failure, the system can store a message and display it on the sign-in page after logout.

4. Access Model and Visibility Rules

The system decides what to show by combining role data, permission data, and session context. This is why two users looking at the same deployment can have very different navigation.

Rule Practical meaning for the user
Role and permission based navigation Modules appear only if the current role includes one of the permissions required by that menu item.
Super Admin and Admin shortcut These roles are treated as fully allowed by the frontend permission helper, so permission-gated controls are visible to them.
Central vs tenant session The same user may see different modules depending on whether the app is running in central mode or tenant mode.
Tab-level access inside modules For example, the Security page can show Operators, Roles, and Permissions tabs independently based on separate permissions.
Action-level access inside pages A user may be allowed to view a table but not create, edit, export, archive, or delete records from it.
Common reasons a module is hidden
  • The permission required by the navigation item is missing.
  • The user is in tenant context and the module is central-only.
  • The page is available but some inner tabs are restricted.
Common reasons a button is hidden or disabled
  • The user has view access but not create, update, or delete access.
  • The record is protected, such as some built-in roles or protected users.
  • The current page mode, such as archived logs or trash, changes which actions are available.

5. Shared Interface and Common Controls

Desktop sidebar

The desktop sidebar is the main module launcher and can be collapsed or expanded.

Always important

  • Shows the current brand logo or sidebar icon based on theme and collapse state.
  • Supports collapsed and expanded navigation states.
  • Shows primary navigation such as Dashboard, Tenant Management, Identity & Access, and Audit Logs when allowed.
  • Shows secondary navigation such as Storage, Settings, and API Docs when allowed.

Additional controls

  • Includes an Apps & Tools expandable section where the Document Converter appears.
  • Provides a Disconnect Node action for logout.
  • Includes a theme switcher inside the sidebar itself.
  • Participates in the guided tour flow.

Mobile navigation

On small screens, users open navigation through the mobile sidebar sheet.

  • Search the menu directly from the mobile sidebar.
  • See only the modules permitted for the session.
  • Hide central-only Tenant Management automatically when the user is on a tenant node.
  • Use disconnect and theme controls without leaving the menu.

Topbar controls

The topbar gives users fast access to system-wide helpers no matter which module they are in.

Global Search

Search the ecosystem for users, nodes, settings, or logs without manually opening each page.

Language Switcher

Theme Toggle

Switch visual theme behavior directly from the topbar.

Fullscreen / Focus Mode

Expand the dashboard into fullscreen mode for concentrated work.

Notifications and Alerts

Profile Menu

Jump to Profile Settings or disconnect from the system.

6.2 Tenant Management

This is the central control workspace for provisioning and operating tenant nodes. It is intentionally blocked in tenant context.

  • Search the tenant matrix by ID or organization name.
  • Copy, export, print, or refresh the tenant table.
  • Open tenant details to review node status, plan, domain, and Super Admin contact information.
  • Provision a new tenant with name, plan, routing address, and Super Admin credentials.
  • Toggle tenant network status between online and suspended when allowed.
  • Enable or disable Super Admin login for the tenant.
  • Reconfigure existing nodes.
  • Purge tenant records and associated data when allowed.
High-impact actions: suspend, Super Admin access toggle, and purge are powerful operations. They should be limited to trusted administrators because they directly affect tenant availability and access.

7. Common User Workflows

Workflow A. Sign in and complete 2FA

1Open the correct central or tenant sign-in page.
2Enter email and password, then submit the login form.
3If prompted, open the authenticator app and enter the 6-digit code.
4If forced setup appears, scan the QR code first and then confirm the first code.
5After success, continue to the dashboard.

Workflow B. Invite a new operator

1Open /dashboard/security and stay on the Operators tab.
2Select the new operator button if it is visible for the role.
3Enter identity details and assign the correct role.
4Save the operator and verify they appear in the table.

Workflow C. Provision a tenant node

1Open Tenant Management from the sidebar.
2Select Provision Node.
3Enter organization name, capacity plan, routing address, and Super Admin credentials.
4Submit the form and confirm the node appears in the matrix.

Workflow D. Upload and manage a file

1Open Storage.
2Select the upload action or drag a file into the upload zone.
3Choose the destination folder and optionally set a base name or custom thumbnail.
4After upload, preview, rename, favorite, share, move, or trash the file as needed.

Workflow E. Enable 2FA from Profile Settings

1Open Profile Settings from the topbar profile menu.
2Switch to the Security tab.
3Enter the current password to begin 2FA setup.
4Scan the QR code and enter the verification code.
5Copy and securely store the recovery codes.

Workflow F. Generate a PDF from the converter

1Open the converter from Apps & Tools.
2Load an HTML file, choose IDE mode, or select a cloud HTML document.
3Add supporting assets if the HTML refers to local files.
4Choose paper size, orientation, background printing, and margins.
5Generate the PDF, review it, and save it to the storage workspace.

8. Troubleshooting

What the user sees Most likely explanation What to check
A module is missing from the sidebar The role lacks the required permission, or the user is in tenant context where the module is intentionally hidden. Confirm the user role and whether the session is central or tenant.
The user lands back on sign-in The token is missing, expired, or blocked. Sign in again and verify the account is still active.
The 2FA page appears after entering password The account requires 2FA, or global 2FA is enforced. Complete the 2FA step or finish the first-time setup.
A page opens but some buttons are missing The user has page visibility but not action-level permission. Check whether create, edit, delete, export, archive, or manage permissions are assigned.
Settings shows only one tab Settings access is tab-specific. Verify which of the brand, general, localization, or backup permissions are assigned.
Tenant Management redirects away The user is in tenant context or lacks tenant management rights. Use a central session and verify view_tenants or tenant management permissions.
Storage actions are unavailable The user is missing the storage permission. Verify manage_storage.
Alert dismissal buttons are disabled The user can view alerts but cannot manage them. Verify manage_alerts.
